## 这是什么项目？

**First Contribution Playground** 是一个对初学者友好的开源仓库，用来练习真实的 GitHub 协作流程。

你可以通过以下方式参与贡献：

- 修复一个小 typo 或文档问题
- 把文档翻译成你的语言
- 添加一个小型 CLI、网页或算法游戏
- 改进文档和新手指南
- 修复网站或仓库中的小问题

目标不是一开始就做到完美，而是学习完整流程：fork、创建分支、编辑、commit、push、发起 PR、接收反馈，然后合并。

---

## 我为什么做这个项目

很多初级开发者都想参与开源，但大多数仓库对第一次提 PR 的人来说都太大、太复杂，也容易让人望而生畏。

我做这个项目，是想提供一个更小、更有引导性的练习场，让初学者可以先在这里练习 issue、分支、pull request、CI 检查、代码评审和合并，而不用一上来就先理解一个庞大的代码库。

---

## 维护者视角的亮点

这个项目刻意保持简单，但同时也包含了一个真实开源仓库需要维护的关键部分：

- 面向游戏、翻译、生成数据和安全规则的自动化 PR 校验
- 对初学者友好的 issue 标签，方便 GitHub 推荐给首次贡献者
- 基于仓库数据生成的 GitHub Pages 网站
- 自动生成的游戏、贡献者和排行榜索引
- 面向新贡献者的反滥用检查和友好的 CI 评论
- 面向翻译、游戏、标签和社区引导任务的独立工作流

## 不需要本地开发环境

对于文档和翻译类任务，你可以直接在 GitHub 网页上完成你的第一个 PR：

1. 在 GitHub 上打开目标文件。
2. 点击铅笔图标。
3. 进行编辑。
4. 点击 **Commit changes**。
5. 选择 **Create a new branch**。
6. 发起一个 pull request。

这是在本地不安装 Git 的情况下，完成第一次贡献的最简单方式。

## 开始处理 Issue 之前

为了避免重复劳动：

1. 打开你想做的 issue。
2. 留言：`I'd like to work on this`。
3. 等维护者确认，或者给它加上 `claimed` 标签。
4. 发起 PR 时，在描述里带上 `Closes #ISSUE_NUMBER`。

如果一个已认领的 issue 7 天内没有进展，它可能会被释放出来，让其他初学者接手尝试。

## 快速开始

### 提交一个翻译

1. 选择一个开放的[翻译类 Issue](https://github.com/AbdullahOztoprak/first-contribution-playground/issues?q=is%3Aissue+is%3Aopen+label%3A%22%F0%9F%8C%8D+translation%22)。
2. 留言 `I'd like to work on this`。
3. 创建对应要求的文件，例如 `translations/README/README.es.md`。
4. 保持标题、链接、列表和代码块结构不变。
5. 使用[翻译模板](../../.github/PULL_REQUEST_TEMPLATE/translation_submission.md)发起 PR。

### 提交一个游戏

1. Fork 这个仓库。
2. 创建分支：`git checkout -b game/your-game-name`。
3. 在 `games/{category}/your-game-name/` 中添加你的游戏。
4. 包含以下内容：
   - `README.md`，说明如何游玩以及你学到了什么
   - `metadata.json`，填写游戏信息
   - 你的源代码
5. 使用[游戏模板](../../.github/PULL_REQUEST_TEMPLATE/game_submission.md)发起 PR。

游戏提交应保持小巧：最多 5 个文件、最多 500 行。

## 生成的数据文件

请不要在贡献分支中编辑这些文件：

- `data/games.json`
- `data/contributors.json`
- `data/leaderboard.json`

它们会根据源文件自动生成。如果你在本地运行了 `npm run build:data`，可以预览结果，但不要提交生成出来的 JSON 改动。
